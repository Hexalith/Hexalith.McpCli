## Findings

### F1 — Advertised output schemas omit declared semantic constraints

**Blocking; fix now.** The new exporter closes object members, controls nullability and required fields, and constrains command status, operation kind, and error-code branches (`src/Hexalith.McpCli.Mcp/McpOutputSchema.cs:21-62,67-110`). It does not encode several normative §G value, cardinality, or conditional-presence rules. Capturing `tools/list` from the built server and evaluating its actual schemas with `jsonschema==4.26.0` accepted all twelve invalid documents below. The schema tests pass because their mutations cover closure, missing unconditional fields, nulls, numeric types, kind/status and error discriminators, without these semantic mutations (`tests/Hexalith.McpCli.Mcp.Tests/McpOutputSchemaTests.cs:216-278,289-347,390-405`). An independent contract-reconciliation pass confirmed the gap.

| Advertised schema accepts | Declared rule violated in PRD addendum §G |
|---|---|
| Query `paging.pageSize: 0` | Positive integer (`addendum.md:328`) |
| Query `paging.offset: -1` | Nonnegative integer (`:327`) |
| Query `paging.totalCount: -1` | Nonnegative integer (`:327`) |
| Query `paging.nextCursor: ""` | Nonempty string when present (`:341`) |
| Command `messageId: "not-a-ulid"` | ULID string (`:335`) |
| Module `operationCount: -1` | Nonnegative integer (`:327`) |
| Module `name: ""`, `description: ""` | Nonempty strings (`:324-326`) |
| `validation_failed` with `violations: []` | Nonempty violations (`:428`) |
| `unknown_module` with four suggestions | At most three suggestions (`:418-423`) |
| Description `submittable: false` without `reason` | Reason required when unavailable (`:316,334`) |
| Lint finding `code: "not-a-code"`, `severity: "fatal"` | Declared lint codes and severity `warning` (`:371-376`) |
| `missing_property_description` without `property` | Property-level finding requires a pointer (`:316,374-376`) |

**Impact:** the advertised contract accepts documents forbidden by FR-11, so the schema-conformance acceptance criterion is incomplete even though the exercised runtime results are correct (`epics.md:1048-1051`; `prd.md:288,296`). This is an advertised-schema defect, not evidence that production emitted these invalid documents. **Prevention:** derive semantic rules from Core-owned contract metadata and include independently specified negative fixtures for each §G constraint, rather than treating valid results plus structural mutations as complete conformance. Preserve open embedded JSON. A generic aggregate schema can enforce common Gateway syntax without assuming every module uses ULIDs.

Reproduction: run `python3 /tmp/mcpcli-epic3-retro-4w523978/runtime_probe.py` to capture the advertisement, then `uv run --no-project --with jsonschema==4.26.0 python /tmp/mcpcli-epic3-retro-4w523978/check_schema_mutations.py`. Captured schemas, full invalid documents, and evaluations are `advertised-tools.json`, `schema-mutations.json`, and `schema-mutations.log` in that directory. The examples above preserve the finding if temporary files expire.

### F2 — Malformed MCP envelopes and colliding argument names report internal faults

**Nonblocking hardening; fix now as proposed work.** Raw stdio calls with arguments containing both `pageSize: 25` and `PageSize: 25`, both `offset: 0` and `Offset: 0`, or both `x: 1` and `X: 2` return JSON-RPC `-32603` with `An error occurred.` A `tools/call` envelope with `params: []` or `params: 42` also returns `-32603`, and SDK deserialization logs a `JsonException` to stderr. The incoming filter matches only an object `Params`, then accesses the argument object before dispatch (`src/Hexalith.McpCli.Mcp/McpCliMcpServiceCollectionExtensions.cs:59-83`). Evidence: `adversarial-duplicates.log:3-7,16-17,87-107` in the run directory; the parent re-read those responses and source paths.

These calls fail before successful execution and the session remains usable. The envelope predicate and some object access predate this epic, so this is not claimed as a newly introduced regression or the reason for rejection. Existing paging verification uses canonical keys only (`McpExecutionTests.cs:219-236,339-358`; `McpStdioProcessTests.cs:199-212`). The adversarial and verification-gap lenses overlap here. **Prevention:** validate the outer call shape and SDK-case-colliding names before binding, return `InvalidParams`, and protect that boundary through raw stdio assertions, including both channels and no Gateway submission.

The narrower suspicion in `deferred-work.md:464-465` was **not reproduced**: uppercase-only `PageSize: 2147483648` and `Offset: 2147483648` return the intended `-32602` Int32 error. Do not describe F2 as an uppercase-only paging bypass.
