## Intent

**Problem:** Parser errors print usage and exit 1, breaking the Epic 2 script contract. Empty tables contain a spurious row, HTTP refusal omits the release cue, and bad result paths can fail after a Gateway call or profile mutation.

**Approach:** Route parser failures through the existing error writer, fix tables and HTTP wording, and preflight predictable output failures before side effects. Test and document the cross-verb contract.

## Boundaries & Constraints

**Always:** Exit 0 means result, 1 means only `describe --lint` findings, and 2 means no result. Non-MCP errors are one `{ "error": ... }` JSON object on stdout, regardless of format/output; pre-request MCP errors use stderr and leave stdout empty. Parse failures use safe `invalid_arguments` messages without raw token values. Preserve help/version. JSON uses the canonical serializer; only discovery/config displays use tables. Diagnostics and format notes use stderr. Preflight predictable output failures before Gateway calls or profile mutations while preserving file, link, permission, and device behavior. Document residual runtime write failures.

**Never:** Change Core records, Gateway semantics, Profile transactions, MCP JSON-RPC, or `references/`. Preserve JSON escaping and Story 2.2's explicit `activeProfile: null` clear result.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|---------------------------|----------------|
| Parse | Unknown verb/option, surplus config token, missing value, invalid/overflowing number | No action, help, token echo, Gateway request, or profile write | `invalid_arguments`, exit 2; MCP startup uses stderr |
| Result | Discovery, config, describe, send, query; default or `--output` | Canonical document on stdout or file; file output leaves stdout empty | No-result failure leaves existing file intact |
| Table | Empty/nonempty discovery, config, JSON-only verbs | Header plus actual rows; JSON-only verbs emit JSON and one stderr note | Same exit, including lint exit 1 |
| Preflight | Unusable output path on send/query/config mutation | No Gateway request/profile change; target intact | Safe `internal_error`, exit 2 |
| Catalog/MCP | Diagnostics, `--strict`, HTTP transport | Diagnostics on stderr; HTTP refused before Catalog | Strict `catalog_invalid`; HTTP `unsupported_transport` and next-release cue on stderr, empty stdout |

**Acceptance Criteria:**
- Given any non-MCP result or no-result failure, when a shell script captures stdout, stderr, status, and an optional output file, then exactly the documented destination contains the document and status is 0, 1, or 2 according to the result contract.

- Given `mcp --transport http`, when the CLI parses transport before Catalog construction, then stderr contains `unsupported_transport` and a next-release message, stdout is empty, and status is 2.

## Design Notes

Map recognized option failures to their public argument (`pageSize`, `offset`, `tenant`, etc.); use `arguments` for unmatched command syntax. Never include `ParseError.Message` verbatim because it can contain a token or secret. Preflight detects ordinary path/permission failures before an action; it cannot promise that a later disk or device write succeeds. Keep Story 2.2's explicit null for `config use --clear`; addendum §G lists generic tool documents, not config management result shapes.

The result writer stages new regular files beside the destination and existing regular files, plus their backups, under `Path.GetTempPath()`. Preflight must probe the location the writer will actually use. A path occupied by an unsupported file type, an invalid proc fd, or an unusable symlink target must fail before a request or mutation. Distinguish regular files from pipes/devices without opening a FIFO in blocking mode, including when a platform-specific file-type call is unavailable; do not reject a write-only FIFO solely because it lacks read permission. Match the writer's Windows sharing requirements for existing regular files. These checks must not open or alter the requested result target's contents. Test unavailable staging in an isolated process so a temporary-directory environment override cannot affect parallel tests.

System.CommandLine may suppress other parser errors when help or version is present. A bare `--help` at the root or any command depth and bare `--version` must keep their successful output, while malformed tokens mixed with either return the normal safe parser failure; do not infer missing-subcommand errors from a reparse after removing help/version. ProfileStore validation includes supplied names, fields, values, and profile records, not just missing operands; a failing config call produces its own error before result-path checks. For table output, escape raw text cells and leave JSON-serialized configuration values unchanged so consumers can parse them. On FreeBSD, the current `struct stat` puts `st_mode` after `st_nlink` at offset 24 on 64-bit layouts; use verified native layouts or an equivalent safe file-type API. A device with no write permission must be refused before mutation. The staging process test must launch the executable beside the currently running test assembly and set the platform's actual temporary-directory and user-profile variables.

Inspect original argument tokens as well as parser errors: System.CommandLine can bind an unknown option-shaped token to an optional positional argument or as a missing option's value. Recognized option names must come from the command tree, not a substring check that mistakes a payload value for a flag. A missing `operations` module or other argument that guarantees no result must retain its `invalid_arguments` response even with an unusable output path. On Unix, permission bits from another identity class do not grant access to the current owner. For FIFOs, a nonblocking access probe may distinguish permission denial from a temporarily absent reader; absence of a reader is runtime pipe behavior and must not turn a potentially usable pipe into a preflight failure. Do not write any bytes during the probe. Existing Windows tests establish that setting `HOME`/`USERPROFILE` does not reliably redirect `ProfileStore`'s production path; use injected stores for mutation tests on Windows and skip an isolated child-process mutation test there unless it can select an exact private profile path.

Option scanning must follow the selected command and inherited globals. Treat unknown single- and double-dash tokens as malformed when they stand alone, occupy an optional positional, or supply an invalid transport; preserve existing dash-prefixed values for recognized options such as `--tenant -a`, `--aggregate-id -a`, and `--entity-id -a`. After the explicit `--` end-of-options marker, dash-prefixed positional values are literal. A valueless help/version flag with an attached value is malformed. Bare help at each command depth remains valid; help combined with partial supplied operands does not erase a missing-operand error. Output preflight is needed before side effects, but a discovered no-result error must be emitted without consulting `--output`; `--output` is only a successful result destination. Linux effective access checks account for POSIX ACL grants, so a separate owner/group/other bit test must not contradict a successful ACL-aware probe. The baseline requires each new enum in its own `.cs` file.

Use one checked parse and semantic validation path for help aliases `--help`, `-h`, `-?`, and `/?`: identify actual help tokens only before `--`, preserve literal positional help values afterward, and distinguish bare help (no supplied operands or values) from a partially specified invocation. With help present, validation must still catch malformed Boolean conversions, empty names, missing send/query operations even when payload is provided, invalid global URL/format, config values, and unsupported HTTP transport. The transport refusal must take the MCP stderr path; non-MCP malformed input must produce one `invalid_arguments` document without echoing values. Known option names with malformed Boolean values must be reported using their public argument names even when System.CommandLine has no `OptionResult` for the error.

The Core executor performs catalog lookup, availability checks, payload and envelope validation, then calls the Gateway. Insert a narrow optional pre-submit preflight callback at that single boundary so a no-result Core error wins without probing `--output`, and a valid send/query checks the destination before calling the Gateway. Do not run Core validation twice, regenerate identifiers, or move a Gateway call. Existing CLI discovery/config no-result checks retain the same precedence. On Windows, `File.Exists` does not distinguish missing from access denied; use an attributes probe that treats only confirmed not-found states as missing, and fail closed on denied or unknown states without touching the target. Add CLI-level existing-file and valid-link success cases, plus invalid add/remove with bad destination, so preflight cannot silently reject valid targets or mask profile errors.
