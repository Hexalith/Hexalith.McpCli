# EventStore Admin migration inventory v1 candidate

Candidate **1.0.0-candidate.3** inventories both proprietary EventStore
administration heads at the full source revision above: the
`eventstore-admin` CLI (`Hexalith.EventStore.Admin.Cli`) and the stdio MCP
server (`Hexalith.EventStore.Admin.Mcp`). The source checkout was clean. It
records **31 registered CLI operations** (21 remote, seven local and three
registered unavailable stubs), **six unregistered CLI helper classes**, and
**28 MCP tools** (18 reads and diagnostics, seven caller-confirmed writes and
three process-local context tools). The MCP server registers no resources,
prompts or lifecycle subscriptions. Counts describe source registrations, not
a live host, authenticated visibility or behavior proof.

Every row proposes **defer / exclude**. No row has a gateway-ready decorated
Command or Query, a canonical McpCli operation or an approved generic
administration contract. No replacement is invented here. Disposition values
are proposals until [A0](#a0-approval-pending) is replaced by an actual owner
approval record. This inventory is migration documentation outside `src/`,
never runtime configuration or execution authority.

migration plan 1.1.0 (`references/Hexalith.AI.Tools/hexalith-mcpcli-migration-instructions.md:2`) lists as outstanding
(`references/Hexalith.AI.Tools/hexalith-mcpcli-migration-instructions.md:36`). Its

## Authority and eligibility model

These rules apply to every remote row. Each row states its own route, policy
and tenant-filter evidence.

- **Human gate and roles:** every Admin.Server controller requires
  `EventStoreHuman` plus a role policy. `AdminReadOnly` admits ReadOnly,
  Operator and Admin roles; `AdminOperator` admits Operator and Admin;
  `AdminFull` requires Admin (AV09). Combined class and action policies all
  apply.
- **Tenant filter:** where marked, `AdminTenantAuthorizationFilter` checks the
  canonical requested tenant against the caller's tenant grants, or admits an
  explicit platform scope for the cataloged platform actions (AV10). It acts
  only when the action has a `tenantId` parameter or a platform-scope
  admission; otherwise it forwards without a grant check
  (`Server/Authorization/AdminTenantAuthorizationFilter.cs:25`). Among the
  actions the heads reach, only `TriggerCheck` (AM06) is such a body-only
  action (`Server/Controllers/AdminConsistencyController.cs:100`): its
  controller admits any requested tenant for Admin-role callers and otherwise
  requires a matching tenant claim
  (`Server/Controllers/AdminConsistencyController.cs:161`). A session or
  remembered tenant is a filter value, never authority.
- **UI-only (AD-11/AD-14):** Platform AD-11 keeps Admin.Server and Admin.UI a
  confidential UI surface until a Platform AD admits a non-gateway
  administration capability under AD-14 (`references/Hexalith.Platform/_bmad-output/planning-artifacts/architecture/architecture-platform-2026-09-27/ARCHITECTURE-SPINE.md:185`). Under AD-14, McpCli
  is a public `agent` client and admits only agent-eligible operations
  (`references/Hexalith.Platform/_bmad-output/planning-artifacts/architecture/architecture-platform-2026-09-27/ARCHITECTURE-SPINE.md:211`, `:213`). No Admin route has
  a declared agent eligibility, so public McpCli execution is denied for every
  remote row.
- **Confirmation-required:** the seven MCP write tools default to a preview
  and send a request only when the caller supplies `confirm: true` (AV07). That
  Boolean is caller input. It proves no human authority, carries no
  confirmation to the server and cannot satisfy AD-14's denial of
  confirmation-required operations through a public client. The CLI mutations
  have no prompt and no confirmation flag at all.
- **Destructive effect** is recorded separately from confirmation and
  eligibility: a destructive row is no more or less eligible because of its
  guard.
