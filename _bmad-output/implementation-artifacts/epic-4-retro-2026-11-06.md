### F2 — The publication history breaks AD-17's one-time bootstrap and shared version (fix the guard now; reconcile the spec)

- **What AD-17 requires:** "a one-time bootstrap phase … publish only that package before upstream decoration begins … Both published packages share one version from that point onward" (`architecture/…/ARCHITECTURE-SPINE.md:160`).

No spec, sprint entry, ledger row or README records or authorizes it. The only mentions are incidental: the rejected `spec-4-14:515,608,709` findings and 4.16 evidence.

- **What still allows it:**
  - Abstractions-only bootstrap is now closed only by the presence of the lightweight tag `mcpcli-paired-publication-started` (`scripts/release-request.py:72-81`).
  - The check is skipped whenever `MCPCLI_RECOVERY_VERSION` is non-empty (`release-request.py:115`; `scripts/verify-release-source.py:155`).
  - `bootstrap` is still a dispatch choice (`.github/workflows/release.yml:10`).
- **Bootstrap pushes get weaker integrity checks than paired pushes:** no post-push public download or comparison, no nuspec commit binding, and different build flags (`scripts/release-publish.sh:17-43`, `scripts/validate-release-packages.py`; adversarial lens, verified by reading the code).

The back-to-back push loop has not yet run in production: 2.0.1 was pushed by the earlier code, with an 8-minute gap (`spec-4-18:93`).
- **Instance:** propose these guard fixes:
  - refuse bootstrap whenever `Hexalith.McpCli` has any published version on nuget.org, independently of the tag;
  - key the skip on `--tagged-recovery` only;
  - restrict `bootstrap` to tagged historical recovery.
  Record a human decision that 1.1.0 and 2.0.0 are accepted historical deviations from AD-17. Defer a completion mode for a stranded pair.
- **Prevention:** an architecture rule that says "one-time" needs an executable latch keyed on registry state, not on a deletable marker.

### F7 — Tenant canonicalization lets one non-ASCII input alias an ASCII tenant (defer upstream; low)

- **Reproduced on the published tool:** `--tenant "Kelvin"` spelled with U+212A KELVIN SIGN goes out on the wire as `"tenant":"kelvin"` (local capture listener).
- The aggregate pass scanned every code point from U+0080 to U+10FFFF. Only U+212A lowercases into ASCII, so `system` is unreachable this way.
- The behavior is shared with the Gateway contract: EventStore `TenantCanonicalizer.TryCanonicalize` does the same `ToLowerInvariant()` (`references/Hexalith.EventStore/src/Hexalith.EventStore.Contracts/Identity/TenantCanonicalizer.cs:21`). This is therefore not a client/server mismatch, and Gateway grants still authorize the resolved tenant.
- The payload tenant member is still compared ordinally against the lowercased value (`OperationExecutor.cs:143-147`). So `--tenant Acme` with payload `"Acme"` is rejected as a disagreement (adversarial lens; read from the code).
- No test covers non-ASCII tenant input.
- **Instance:** defer to the EventStore owner (refuse non-ASCII before lowercasing), then mirror the fix and add tests in McpCli.
- **Prevention:** a canonicalization contract needs negative tests for non-ASCII input.
