## Findings

### Aggregate architecture and spec reconciliation

1. **Blocking: valid Query payloads cannot all be represented by v1 vectors.** The built `sample.get-item` Catalog schema accepts JSON `null` (compiled Catalog and `PayloadValidator` probe). `SchemaDeriver` normalizes only Command roots (`src/Hexalith.McpCli.Core/Schema/SchemaDeriver.cs:78-89`), and the executor can forward a null Query Payload (`src/Hexalith.McpCli.Core/Execution/OperationExecutor.cs:227-230`). The vector schema requires an object at every step (`tools/conformance-vectors/v1/schema.json:92-100`), and the validator also requires an object in the expected request (`tools/conformance-vectors/v1/validate.py:134-135`). This contradicts the declared compatible Payload-input contract (`_bmad-output/planning-artifacts/epics.md:484-492`). **Disposition:** fix now. Make Query vector shape follow its Catalog schema while retaining the Command object rule. Prevent recurrence by testing every accepted Query root shape against the author validator.

2. **Blocking: Query projection routing is absent from the sample's approved request.** The validator requires `domain`, `aggregateId`, and `queryType`, but not `projectionType` (`tools/conformance-vectors/v1/validate.py:129-135`). The sample Query omits it (`tools/conformance-vectors/v1/sample-query.json:18-25`) and still passes its validator test (`tools/conformance-vectors/v1/test_validate.py:63-66`). Loopback compares only the keys supplied in the expectation (`tools/conformance-vectors/v1/run_loopback.py:96-105,418-427`), so both Heads can use one wrong projection and still pass. The Core test covers only the synthetic sample's projection (`tests/Hexalith.McpCli.Core.Tests/OperationExecutorTests.cs:169-175`). **Disposition:** fix now. Require nonblank `projectionType` for every Query step, and test missing and wrong values in each step position. Prevent recurrence by deriving the required expectation fields from the Gateway request contract.

3. **Blocking: offline approval accepts impossible Gateway request fields.** `expectedGateway.body` is open in the schema (`tools/conformance-vectors/v1/schema.json:48-56`), and the validator denies only selected wrong-kind or unsent fields (`tools/conformance-vectors/v1/validate.py:111-128`). A direct validator probe accepted an invented `body.bogus` field, which Core's fixed `SubmitCommandRequest` and `SubmitQueryRequest` construction cannot emit (`src/Hexalith.McpCli.Core/Execution/OperationExecutor.cs:217-234`). Story 1.8 declares a closed expected-request format (`_bmad-output/planning-artifacts/epics.md:484-487`). **Disposition:** fix now with finding 2. Close Gateway-owned fields while leaving Module Payload JSON open; add a negative unknown-field fixture.

4. **Invalid tenant syntax can pass author validation but fail execution.** A direct validator probe accepted envelope and expected-body tenant `" bad tenant "` (`tools/conformance-vectors/v1/schema.json:29-36`; `tools/conformance-vectors/v1/validate.py:129-130`). Core rejects it before Gateway submission (`src/Hexalith.McpCli.Core/Execution/OperationExecutor.cs:112-121`). This was already deferred at `_bmad-output/implementation-artifacts/deferred-work.md:120-122`. **Disposition:** propose fixing now with the Gateway expectation work in finding 2, using the existing ledger entry rather than creating another. Prevention: share the pinned Gateway grammar between author validation and runtime tests.

5. **Guidance drift: the project allowlist omits an accepted dependency.** `AGENTS.md:82` permits the EventStore client, Contracts libraries, and the EventStore.Contracts closure. Core directly references `JsonSchema.Net` (`src/Hexalith.McpCli.Core/Hexalith.McpCli.Core.csproj:11`), and the tracked dependency policy permits 9.4.0 (`tools/dependency-policy.json:7,32`); Story 1.3 requires it (`_bmad-output/planning-artifacts/epics.md:300-305`). The mismatch is already logged at `_bmad-output/implementation-artifacts/deferred-work.md:13`. **Disposition:** fix now as guidance reconciliation, keeping the dependency decision. Prevention: compare managed project context with executable dependency policy on each allowlist change.

6. **Contract wording drift: String identifiers have two definitions.** `IdentifierKind.String` documents non-empty strings (`src/Hexalith.McpCli.Abstractions/IdentifierKind.cs:11`), while Story 1.3 explicitly decided String kind admits any string (`_bmad-output/implementation-artifacts/spec-1-3-derive-the-operation-s-json-schema.md:83`). `SchemaDeriver` adds no `minLength` for marked String identifiers (`src/Hexalith.McpCli.Core/Schema/SchemaDeriver.cs:299-310`); a compiled probe accepted an empty marked, non-routing identifier. Aggregate identifiers have a separate non-empty check (`src/Hexalith.McpCli.Core/Execution/OperationExecutor.cs:202-214`). **Disposition:** defer a product/architecture decision and reconcile the text or schema accordingly; this contradiction alone does not establish a runtime failure.

The project reference graph follows the architecture's Abstractions → Core → adapters direction (`src/Hexalith.McpCli.Core/Hexalith.McpCli.Core.csproj:7-13`; `src/Hexalith.McpCli.Mcp/Hexalith.McpCli.Mcp.csproj:7-8`; `src/Hexalith.McpCli/Hexalith.McpCli.csproj:20-28`; architecture spine AD-1/AD-2 at lines 44-68). The 530-line `SchemaDeriver.cs` was inspected as the largest relevant production file; its exporter, transform, and converter checks are closely related, so size alone is not a god-class finding. No separately evidenced duplication or architecture cycle was found in this scope. The production Catalog 500 ms CI gate belongs to Story 4.11 (`_bmad-output/planning-artifacts/epics.md:1393,1414-1416`), so it is not counted as an Epic 1 failure.

## Acceptance verdict

**Rejected (machine verdict; declared criteria).** All stories are marked done and the Catalog, analyzer, manifest, and sample loopback evidence is substantial. Yet Story 1.8 calls for a versioned, closed contract fixing compatible Payload inputs and expected Gateway requests (`_bmad-output/planning-artifacts/epics.md:482-497`). The current format rejects a Query Payload its built Catalog accepts (finding 1), while offline approval accepts request expectations missing projection routing or containing impossible fields (findings 2–3). These are open blocking criteria failures. A human acceptance decision can override the machine verdict; none was supplied during this run.
