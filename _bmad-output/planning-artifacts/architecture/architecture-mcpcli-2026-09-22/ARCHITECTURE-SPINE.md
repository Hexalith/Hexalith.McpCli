# Architecture Spine — Hexalith.McpCli

## Design Paradigm

**Hexagonal.** One core that knows Contracts types, the Catalog, validation, the Envelope, and the gateway port. Two adapters (the MCP Server head and the CLI head) that translate their protocol into the core's call model and back, and nothing else. The gateway client, the settings sources, and id generation are ports.

**What ships.** The first public pair was 2.0.1. The 3.0.0 tool released on 15 November contains Parties and Tenants. At McpCli revision `e79b7f8b`, the same shared executor serves 26 Operations across Parties (7), Tenants (15) and Projects (4). Projects still needs populated, authorized reads and denial evidence. Folders has published its Contracts and Aspire helper. Two restricted command declarations and outstanding Gateway work still block its enrollment (AD-15/23). The next stable tool release requires a publishing decision and archive verification under AD-17. [Public release](https://github.com/Hexalith/Hexalith.McpCli/releases/tag/v3.0.0) · [Source cohort and qualification](../../prds/prd-mcpcli-2026-09-21/prd.md#module-enrollment-on-2026-11-20)

**Ecosystem boundary.** Both Heads expose eligible Gateway Commands and Queries through one Catalog. AD-23 gives each legacy capability an owner and disposition, including confidential UI, named local-tooling exemptions and withdrawal. Hosted HTTP and stream transport require their own admission decisions. Each proprietary surface keeps its authorization, semantic and retirement gates. [Adopted capability classes](AD-23-non-gateway-capability-classes.md)

## Invariants & Rules

### AD-1 — Heads are translators; the core decides

- **Binds:** all
- **Prevents:** a head validating a Payload, filling an Envelope, enforcing Read-only Mode, resolving settings, or reflecting over a Contracts type on its own, so that the two Heads disagree (SM-4).
- **Rule:** `Hexalith.McpCli.Core` references no MCP, System.CommandLine, or ASP.NET package. It owns shared settings values, Catalog, validation, execution, and typed result/error records. A head binds its assigned input to Core argument records (AD-5), calls `ICatalog` or `IOperationExecutor`, and owns transport, tool advertisement, exit-code mapping, rendering, and protocol carriage. Operation handlers consume resolved settings. The CLI composition root resolves the session and its named configuration commands use the shared Profile store under AD-13/14. The MCP tools have no profile-mutation path.

### AD-2 — Dependency direction

- **Binds:** the production projects under `src/`.
- **Prevents:** either Head owning a second Catalog or importing a Module implementation.
- **Rule:** only the tool executable enrolls Module Contracts packages. Core references the EventStore client and envelope contracts directly. The MCP adapter depends on Core. Module producers reference the public Decoration Package. Its analyzer is a private build dependency packaged for authors (AD-18). Test-only composition follows AD-15/16.

### AD-3 — The Catalog is the only view of Contracts types

- **Binds:** Core, both heads, FR-5 to FR-8, FR-19
- **Prevents:** the executor or a head re-reflecting a type and disagreeing with what `describe_operation` showed; two Catalogs in one test; `config` dying on an empty Catalog.
- **Rule:** `CatalogBuilder.Build(IReadOnlyList<Assembly>)` is the only entry point; the composition root passes the generated manifest (AD-4), unit tests pass `Sample.Contracts`. It freezes an immutable model: `ModuleDescriptor(Name, Description, IdentifierKind, FixedTenant, WireTypeConvention, ModulePayloadOptions, Operations)` and `OperationDescriptor(Name, Kind, Description, Example, Schema, Routing, AggregateIdAccessor, AggregateIdConstant, AggregateIdRequired, IdempotencyKeyRequired, EnvelopeFilledProperties, PropertyBindings, ContractType, PlatformScope)` plus `IReadOnlyList<CatalogDiagnostic>`. The marker's `SerializerOptionsProvider` member is a `Type` from the marked Contracts assembly; it must directly declare a public static, non-indexed `Options` property of exact type `JsonSerializerOptions` with a public getter returning a non-null value. The current reflection check requires a getter but accepts a private getter on a public property with a public setter. Core maintainers must check getter visibility and cover that case before claiming full provider validation. The Catalog reads the property exactly once, then caches the AD-6 result as `ModulePayloadOptions`; an absent provider selects the canonical defaults. A foreign provider type, missing getter, thrown exception or null return excludes the entire Module with one assembly-level `invalid_serializer_options_provider` diagnostic. An invalid Module `FixedTenant` also excludes the entire assembly, with one `invalid_routing_value` diagnostic before Operation scanning. Computed Queries may omit both projection selectors. A projection type alone is valid. An actor selector requires a resolved projection type or the Query is excluded with `missing_routing_values`. An Operation's optional `PlatformScope` is validated once with the AD-22 scope grammar; a malformed scope or its combination with Module `FixedTenant` excludes the Operation with `invalid_routing_value`. `PropertyBindings` resolves every declared `aggregateIdProperty`, `tenantProperty`, `correlationProperty`, `idempotencyKeyProperty`, and `actorProperty` once: each string is an exact, case-sensitive top-level CLR property name, never a JSON name or path. Resolve it under `ModulePayloadOptions` to one included, deserializable serialized member and its escaped RFC 6901 pointer; honor `[JsonPropertyName]`. Missing, ignored, ambiguous, or converter-opaque members exclude the Operation with `invalid_property_reference`. Two envelope roles, or an envelope role and `aggregateIdProperty`, must never own the same serialized member: exclude with `conflicting_property_roles`, retaining `tenant_is_aggregate_id` for the tenant/aggregate collision. Schema, filling, ownership checks, and the property accessor all consume this immutable mapping. The Catalog owns Contracts discovery and routing. Its Core schema and serialization components resolve effective member metadata during Catalog construction. The Heads and executor consume the cached descriptors. The Catalog is built lazily by the first verb that needs it; `config`, `--version`, and `mcp --transport http` never touch it; for discovery, `send`, `query` and stdio startup, strict mode with any diagnostic fails first with `catalog_invalid`. Otherwise zero valid Operations across all Modules fails with `catalog_empty`. Both failures exit 2. Scan distinct assemblies by ordinal simple name, then ordinal full assembly name, then module version ID. Within each assembly, scan types by ordinal full CLR name. The first admitted declaration keeps a duplicate name. Diagnose subsequent collisions as `duplicate_module` or `duplicate_operation_name` before sorting the public descriptors. A single immutable Core execution-availability value derives from `ResolvedSettings`: write Operations in Read-only Mode have `submittable: false, reason: read_only`; otherwise a missing Gateway URL gives `submittable: false, reason: configuration_invalid`. `ICatalog.Describe` and executor preflight consume that same value. `ICatalog.ListOperations` returns the Core `unknown_module` error for a nonblank requested Module absent from the Catalog, with up to three nearest declared canonical Module Names ordered by case-insensitive edit distance and ordinal tie-break; missing, empty or whitespace-only required `module` and `operation` strings fail Head binding before lookup. MCP returns JSON-RPC `InvalidParams` (`-32602`). CLI exits 2 with the §G `invalid_arguments` document naming the argument. A genuine lookup miss preserves the supplied spelling. Discovery and MCP startup succeed without a URL; the descriptor carries no session state.

- **Platform-connected discovery and execution (required for qualification).** Core evaluates each locally discoverable Operation for the selected environment. An Operation can execute only if local preflight permits it and fresh metadata from that Gateway serves it as enabled, matches its contract-schema digest, admits the authenticated McpCli surface and supports the caller’s current authorization. Missing, stale or mismatched metadata, ineligible surfaces, disabled Modules and absent permission yield a negative decision. Both Heads report a locally visible Operation missing from the served set as non-executable. AD-23 still controls which declarations can be exposed at all. Neither discovery nor execution enables a Module or falls back to another environment. Recheck availability for invocation. The Gateway authorizes every submitted call and never logs or persists bearer tokens. [Platform discovery and invocation criteria](https://github.com/Hexalith/Hexalith.Platform/blob/25887836c2c7a63edbff7a4e0426e078a188b98c/_bmad-output/planning-artifacts/epics.md#L1914)

- **Proposed connected result contract.** In connected mode, CLI `operations` and `describe` and their MCP equivalents return the same Core-owned boolean `executable` on each listed Operation and its description. Only a positive decision yields `true`. Offline inspection omits the member and makes no executability claim. Existing `submittable` and `reason` retain their §G local-preflight meanings. The proposal requires a versioned change to the two closed §G result schemas and owner agreement on metadata freshness. Until both contracts are agreed, the connected result and its execution path are pending. Check positive, missing, stale, digest-mismatch, ineligible, disabled and denied cases against the same environment through both Heads.

### AD-4 — Assembly manifest is generated from package references

- **Binds:** the executable, its build target, FR-5 and FR-20.
- **Prevents:** an accidental assembly scan or a deployed Catalog that differs from the build manifest.
- **Rule:** mark each enrolled, versionless Module Contracts reference in the executable with `HexalithContracts="true"`. After reference resolution, `Build/ModuleAssemblyManifest.targets` matches each package ID to exactly one copy-local `*.Contracts.dll` with the same assembly name as its filename. It rejects an unflagged direct Contracts package, a missing or ambiguous assembly, or an identity mismatch. It writes the package/assembly pairs to `ModuleAssemblyManifest.g.cs` in ordinal assembly-name order. Before loading those entries, `ManifestLoader` registers the default-context resolver for the host Decoration Package so producer and consumer see the same attribute types. The released tool ships untrimmed. Unmarked assemblies are invisible. A marked empty Module produces `empty_module` and is visible in a usable non-strict Catalog alongside a Module with a valid Operation.

- **Platform run-scoped manifest (required, pending).** For a source-mode run, Platform supplies the manifest generator with its build-time mapping for each enrolled Contracts assembly, including the logical enrollment, expected assembly identity, resolved artifact path and content digest. Resolve each selected entry to exactly one copy-local assembly, verify its assembly metadata and bytes, and generate the same ordinal manifest consumed by the loader. Reject missing, duplicate or ambiguous entries, mismatched bytes or identity, and competing package and source inputs for one enrollment. Never discover replacement DLLs at runtime. Package-mode CI uses the candidate’s Release packages and catalog-pinned dependencies under AD-17. The published McpCli keeps its flagged package path and AD-15 dependency boundary. [Platform manifest override](https://github.com/Hexalith/Hexalith.Platform/blob/25887836c2c7a63edbff7a4e0426e078a188b98c/_bmad-output/planning-artifacts/architecture/architecture-platform-2026-09-27/ARCHITECTURE-SPINE.md#L383)

### AD-5 — One call model, one document set, equal across heads

- **Binds:** Core, both heads, FR-9, FR-11, FR-12, FR-14, SM-4
- **Prevents:** two result dialects; a CLI error shape that differs from the MCP one; a document that cannot be `structuredContent`.
- **Rule:** Core exposes the discovery operations `ICatalog.ListModules()`, `ICatalog.ListOperations(module, kind?)` and `ICatalog.Describe(operation)` and the execution records `SendCommandArguments(Operation, Payload, Tenant?, AggregateId?, CorrelationId?, IdempotencyKey?, Extensions?)`, and `RunQueryArguments(Operation, Payload, Tenant?, AggregateId?, EntityId?, PageSize?, Offset?, Cursor?)`. PRD addendum §G defines the public success and error records, member types, constraints and variants. Emit required members, omit absent optional members and use empty arrays for empty collections. AD-7 records the collection-root Query example gap and AD-9 records the outstanding malformed Command acknowledgment check. A call kind mismatch is `validation_failed` with one violation at `/operation`, regardless of session availability. In particular, `list_modules` contains only `modules`; `describe_operation` includes `envelope`, `lintFindings`, and `submittable`; its Envelope optionally reports either exact `platformScope` or `fixedTenant` and omits `tenant` from `arguments` when either declaration applies; a successful Command includes `operation`, `messageId`, `correlationId`, `tenant`, `aggregateId`, and `status: accepted`, echoing `idempotencyKey` only when caller-supplied and including `result` only when the Gateway returns a payload; a successful Query includes `operation`, `tenant`, and `document` even when the document is JSON null, and includes `paging` only when the returned metadata satisfies AD-20. A malformed response follows the §G `gateway_error` branch. The exhaustive §G error variants include `unknown_module(Code, Module, Suggestions)` for a nonblank `list_operations` lookup miss. CLI binding and MCP semantic argument checks can return `invalid_arguments(Code, Argument, Message)`. Its argument uses the §G enum, including CLI management and parser names. Gateway exceptions retain their integer status, including 2xx. Detail uses the first nonblank exception Detail or Title, then `Gateway request failed.` Optional reason uses ReasonCode, Code, then Reason. Omit absent optional metadata and exception correlation IDs that are not canonical ULIDs. Both execution tools require a nonblank Operation Name and a string containing JSON text. Core parses the string, then validates the decoded value against the Module's Schema. For an available, matching Operation, malformed JSON or a duplicate object member at any nesting depth produces a single `validation_failed` violation at `/` with zero Gateway calls. Inline JSON, `@file` and stdin are CLI input forms. Both heads emit the same Core-owned JSON object with `McpCliJson.Result`, written as text by `McpCliJson.SerializeText`; failures emit only `{ "error": <OperationError> }`. The SDK derives MCP input schemas from the registered tool delegates. AD-12 validates the incoming tool arguments before invoking those delegates. Only the MCP adapter binds per-call `Tenant`; the CLI leaves it null and carries global `--tenant` through `ResolvedSettings` and `EnvelopeContext`. A surface-map test covers addendum §E; contract fixtures cover every §G success and error shape. Equality compares deterministic documents with `JsonElement.DeepEquals` after canonical serialization; AD-16 defines the live-test boundary.

### AD-6 — Serialization policy is owned by Core

- **Binds:** Core, both heads, FR-5, FR-7, FR-15, FR-16
- **Prevents:** the two heads choosing different Payload casing or converters; a Module converter changing Envelope or result serialization; result documents differing across heads.
- **Rule:** `McpCliJson.Payload` is the canonical Payload baseline: `PropertyNamingPolicy = null` and case-sensitive property names (CLR names by default, overridden by `[JsonPropertyName]`; an explicit McpCli wire choice, verified against the current Tenants validator rather than asserted as a universal EventStore convention), `JsonStringEnumConverter`, nulls omitted, `UnmappedMemberHandling = Disallow`. At Catalog build, `McpCliJson.ForModule(contractsAssembly, module)` creates and makes read-only one cached options instance per Module: copies the provider's converters in declared order, then canonical converters, while fixing all non-converter settings to the canonical baseline, including a tool-owned `DefaultJsonTypeInfoResolver` set before `MakeReadOnly()` and Schema export; a provider's resolver is not copied. Schema derivation, identifier-type probing and contract materialization use those Module options. Core parses the raw JSON independently, validates against the Module Schema and preserves its serialized names in the reconstructed Envelope Payload. `McpCliJson.Result` uses web defaults, camelCase, indented JSON, LF newlines and camel-case string enums. Both Heads serialize their documents with it. Their emitted text goes through `McpCliJson.SerializeText`, which writes ASCII: double quotes, backslashes, control characters and non-ASCII characters use JSON escapes, while `'`, `<`, `>`, `&` and `+` appear as written. MCP structured content keeps the `Result` options. The SDK builds input schemas from the registered delegates. Core's `ResultDocumentSchema` publishes the closed §G success/error variants, preserving arbitrary embedded JSON where §G permits it. Envelope fields outside `Payload` always use the gateway client's tool-owned policy; Module options never reach them.

### AD-7 — Schema derivation and validation

- **Binds:** Core, FR-4, FR-7, FR-15, FR-16
- **Prevents:** two schema generators producing different `describe_operation` output; a validator that stops at the first violation.
- **Rule:** the Schema is `JsonSchemaExporter.GetJsonSchemaAsNode(module.ModulePayloadOptions, type)` with one `TransformSchemaNode` in `Hexalith.McpCli.Core.Schema` that adds `description` from `[Description]`, sets `readOnly: true` and removes from `required` each envelope-filled property (AD-9), and types identifiers per AD-8. The resolver keeps effective serializer inputs, including constructor-bound members and getter-only members populated in place under property- or type-level `JsonObjectCreationHandling.Populate`. It omits computed output-only getters such as `ICommandContract.AggregateId`. Fixed-shape records set `additionalProperties: false`. Typed dictionaries accept dynamic keys and constrain each value with its derived `additionalProperties` schema, including any identifier pattern. The existing exclusions for extension data and opaque types still apply. `EnvelopeFilledProperties` is exactly the set named by `tenantProperty`, `correlationProperty`, `idempotencyKeyProperty`, and `actorProperty`; there is no name-based inference, so a `TenantId` not named by `tenantProperty` is ordinary Payload. The Command Schema root is a non-null JSON object even when the exporter emits an object-or-null root; after export, normalize only the top-level `type` to `object` and preserve nullable nested members. Core rejects a null or non-object Command Payload at `/` before envelope filling or accessor use. A Query root follows its declared contract Schema and the pinned Gateway's optional Payload rule. A declared discovery `example` must both be a JSON object and validate against that Schema, because the public `describe_operation` output schema requires an object when the member is present. A Query with a collection root can omit its example and still accept collection Payloads. **Implementation gap from the 20 November PRD validation:** the Catalog currently accepts a schema-valid collection example such as `[]`. Reject the declaration with `invalid_example` and cover it with a collection Query regression and an assertion against the advertised output schema. Validation is `JsonSchema.Net` with `OutputFormat.List`; each violation reports `InstanceLocation` (a JSON Pointer) as its path. The Schema is derived once per Operation at Catalog build and stored on the descriptor. Pre-fill validation retains the original raw Payload for AD-9 ownership checks and validates a copy with only the AD-3 mapped envelope-owned members removed against this stored Schema; ordinary members, unknown names, and root constraints are still checked. No contract deserialization occurs in this pass. After ownership checks and filling, validate the complete rebuilt Payload against the unmodified stored Schema, including envelope-member types and patterns. `readOnly` is descriptive metadata, never the mechanism that skips raw-field validation. `describe --lint` recursively inspects serialized members inside nested objects and collections; each property-level finding carries its escaped RFC 6901 pointer in Module-serialized casing and stays out of Catalog diagnostics.

### AD-8 — Identifiers are marked, never guessed

- **Binds:** Abstractions, Core, FR-7, FR-15, FR-16. Amends PRD FR-7 and §3 (see PRD Amendments).
- **Prevents:** a non-ULID managed tenant identifier such as `acme` failing its own Schema; the sample fixture and real Modules enforcing different kinds for the same value.
- **Rule:** the Module marker declares `IdentifierKind` (`Ulid` or `String`). A property carrying `[HexalithIdentifier]`, or named by `aggregateIdProperty`, gets Schema `{ type: string }` plus the ULID `pattern` when the Module's kind is `Ulid`; its CLR type must serialize as a JSON string under the Module Payload options (a converter-backed value object qualifies; otherwise `invalid_identifier_type` excludes the Operation). A property whose CLR type is `Ulid` gets the pattern regardless. An unmarked identifier-like property retains its serializer-derived Schema and produces only the `unmarked_identifier_like_property` lint finding; no identifier kind is inferred from its name. Catalog admission validates a Query aggregate constant under AD-19. The executor validates the explicit `aggregateId` and the accessor value against the Module kind and the Gateway pattern (AD-9/19). A `Ulid` identifier must have 26 canonical uppercase characters. A `String` identifier must be nonempty and meet the Gateway syntax. Tenant is never ULID-validated. Generated message identifiers and caller-supplied idempotency keys and correlation identifiers are always canonical uppercase ULIDs; the tool never generates an idempotency key.

### AD-9 — The executor fills the Envelope [ADOPTED]

- **Binds:** Core, FR-15 to FR-17, FR-19
- **Prevents:** a Head or caller supplying a message identifier, a silently overwritten disagreement, or automatic retries by either Head or Core.
- **Rule:** `IOperationExecutor.ExecuteAsync(OperationCall, EnvelopeContext, CancellationToken, beforeSubmit?)` runs, in order: resolve the descriptor (else `unknown_operation` with up to three `Suggestions`); reject `SendCommandArguments` for a read descriptor or `RunQueryArguments` for a write descriptor as `validation_failed` at `/operation`; apply the shared execution-availability preflight from AD-3 (`read_only` before missing-URL `configuration_invalid` for a matching write call); parse the raw Payload and run the AD-7 pre-fill validation on its copy without materializing the contract; resolve Tenant, Actor, and Command identifiers; check raw Tenant/Actor values, Command identifiers and extensions or AD-20 Query arguments. Fill the envelope-owned fields, validate the rebuilt Payload, then read the AD-19 accessor and check the aggregate ID. Apply any CLI result-destination preflight before contacting the Gateway. Submit a single request through `IEventStoreGatewayClient` and map the response or `EventStoreGatewayException` to AD-5 records. Tenant precedence is the Operation's exact declared `PlatformScope`, else Module `FixedTenant`, else the public session/per-call tenant under AD-22. Platform and fixed declarations cannot coexist; either ignores the session tenant and requires any per-call value to match exactly using ordinal equality, irrespective of the override gate. For variable-scope calls only, lowercase session and per-call values invariantly without trimming before selection and comparison. A differing per-call value may replace a configured session only when `EnvelopeContext.AllowTenantOverride` is true; matching canonical values need no gate, and a per-call value is used without that gate when no session exists. A missing tenant, disallowed override or public variable-scope `system` value is `validation_failed` at `/tenant`. An Operation naming `actorProperty` requires `EnvelopeContext.Actor`; Actor is never a per-call argument. Exact declaration, Actor, aggregate and raw Payload disagreements use ordinal equality; variable-scope tenant inputs compare after AD-22 canonicalization. Present raw values under `tenantProperty` or `actorProperty` must be JSON strings ordinally equal to the resolved values; null, non-string, or differing values are `validation_failed` at the mapped property pointer. An explicit aggregate identifier differing from the accessor value is `validation_failed` at `/aggregateId`. Before submission, ordinary/fixed Tenant must contain 1–64 lowercase ASCII letters, digits or hyphens and start and end with a letter or digit; an Operation's declared platform scope uses AD-22's separate grammar and cannot be acquired through an ordinary operation's tenant argument; aggregate and entity identifiers must match its alphanumeric, dot, hyphen, and underscore pattern at most 256 characters long with no colon. Tenant and entity violations use `/tenant` and `/entityId`. For aggregate validation, AD-19 selects the error pointer from the source of the value. For Commands, the executor generates `MessageId`, resolves `CorrelationId = Arguments.CorrelationId ?? MessageId`, accepts only a caller-supplied `IdempotencyKey`, validates the present identifiers as canonical uppercase ULIDs, and passes the key only when supplied. Extension validation uses `AllowedExtensions` with ordinal-ignore-case membership, permits at most 32 entries, limits keys to 100 characters and values to 1,000 characters, limits their combined UTF-8 size to 4,096 bytes, and applies the pinned sanitizer's key grammar, control-character, and injection checks. These fixed limits are the intersection of the request validator and the default Gateway sanitizer; a deployment configured more strictly can still return `gateway_error`; violations use `/extensions` or `/extensions/<escaped-key>`. The executor compares supplied `tenantProperty` and `actorProperty` values before filling and overwrites `tenantProperty`, `correlationProperty`, and `actorProperty` with resolved values when declared. It fills `idempotencyKeyProperty` only when a caller supplied a key; without one, a non-null raw value is `validation_failed` at `/idempotencyKey` and a raw null is removed before final validation and submission. Catalog sets one descriptor `IdempotencyKeyRequired` when that property is non-nullable or its effective `JsonPropertyInfo.IsRequired` under `ModulePayloadOptions` is true (C# `required` or `[JsonRequired]`); both `describe_operation` and executor use it, so `idempotencyKeyRequired: true` and an omitted key returns `validation_failed` at `/idempotencyKey` before contract materialization. Queries accept neither correlation identifier nor extensions and put neither into `SubmitQueryRequest`; they overwrite only envelope-filled properties for which the executor has a resolved value. The rebuilt Payload is validated again against the stored Schema before request construction; any violation returns `validation_failed` and the gateway client sees zero calls. An invalid Module `FixedTenant` excludes its entire assembly (AD-3). Invalid Operation routing values, scope declarations, scope/fixed-tenant conflicts and Query aggregate constants exclude the Operation with `invalid_routing_value`. The Envelope uses Routing Values. ### AD-14 — Profile store

- **Binds:** Core `.Settings`, `config` verbs, FR-18
- **Prevents:** one profile name targeting both the admin API and the Gateway; lost concurrent updates, interrupted writes, or transient exposure of a token.
- **Rule:** `ProfileStore` exclusively reads and writes this tool's own file, default `<user-profile>/.eventstore/mcpcli.json`; this tool never opens the admin CLI's `profiles.json`. An explicit constructor file path wins; otherwise an absolute `MCPCLI_HOME` selects `<MCPCLI_HOME>/.eventstore/mcpcli.json` on each supported OS. An unset override retains the default. Empty, whitespace-only, relative, control-character-containing or existing-file overrides fail as `configuration_invalid` without disclosing the supplied path or falling back to the real home. This selector changes store location only, not session-setting precedence or identity; the same transaction, link and permission protections apply at the selected location. Its version-1 shape is `{ "version": 1, "activeProfile": "dev", "profiles": { "dev": { "url": "...", "token": "...", "format": "json", "tenant": "...", "actor": "...", "allowTenantOverride": false, "allowedExtensions": ["task-id"] } } }`. Profile names match `^[a-zA-Z0-9_-]{1,64}$`; unknown versions or fields fail without mutation. All mutations use one transaction: take an exclusive cross-process lock, reload and validate the latest file, apply one change, write and flush a same-directory temporary file with restrictive permissions from creation, then atomically replace the target. On non-Windows, the directory is 700 and profile, temporary, and lock files are 600; on Windows, inheritance is disabled and explicit ACLs grant only the current user and LOCAL SYSTEM access to the directory, profile, temporary, and lock files before any token bytes are written. The target and lock path must be regular files, not symlinks. Interrupted transactions retain either the previous or new complete file; stale temporary files are ignored, and malformed targets fail with `configuration_invalid` rather than being overwritten. `config profile add` requires an explicit name and `--url`. It creates or wholly replaces that profile with only the explicitly supplied URL, token and format. Replacing it clears omitted connection fields and its saved tenant, actor, override flag and extension allowlist. Other profiles and the active selection are preserved. Reject explicit `--tenant`, `--actor` or `--allow-tenant-override` before writing. Use `config set` to change a single operator field. `config profile remove <name>` removes it and clears the active selection if needed; `profile list` lists names and masked tokens; `use <name>` selects an existing profile, while `use --clear` clears it; `current` shows resolved values and sources with masked token; `set <profile> <field> <value>` edits only `tenant`, `actor`, `allowTenantOverride`, and comma-separated `allowedExtensions`. Missing profiles and invalid values fail without a write. Tests cover round trips, concurrent writers, interrupted writes, permissions on Linux and Windows, symlink rejection, and separation from the admin store.

- **Result destinations (implementation gap).** All CLI verbs that write result files must refuse the selected profile path, its lock and its transaction temporary paths, including aliases of those files. Use the resolved path for a missing target and filesystem identity for existing targets, including hard links. Check before any Profile mutation, Gateway submission or result write, and ensure the actual write still targets an allowed file. A detected collision uses the ordinary output-preflight failure (`internal_error` on stdout, exit 2). ### AD-19 — Aggregate identifier resolution

- **Binds:** Core `.Catalog`, `.Execution`, FR-2, FR-16
- **Prevents:** the Catalog and the executor deriving the aggregate identifier differently; interface-routed Commands (whose `AggregateId` is a computed getter with no Payload member) failing every call.
- **Rule:** `OperationDescriptor.AggregateIdAccessor` is a `Func<JsonElement, string?>` compiled once at Catalog build: when `aggregateIdProperty` is set, a read through its AD-3 resolved serialized JSON Pointer; otherwise, for an `ICommandContract` implementer, deserialization of the rebuilt, finally validated Payload into the contract type with the Module Payload options and the interface getter. No contract is materialized from the raw Payload before envelope-owned required members are filled. A Command with neither source is excluded with `missing_routing_values`. Both Query sources are optional, including for a list Query. Check the declaration first. If both `aggregateIdProperty` and `aggregateId` are present, exclude the Query with `ambiguous_aggregate_id` even if the constant is malformed. A sole constant must satisfy both Gateway identifier syntax and the Module’s Identifier Kind. A `Ulid` Module requires a canonical uppercase ULID, checked with the same rule as execution. Exclude a malformed constant at Catalog build with `invalid_routing_value`. The current Catalog checks Gateway syntax alone and can advertise an unusable default. Verify that an admitted constant is optional in discovery and usable by a call that omits the argument. With neither, the Query stays in the Catalog and `describe_operation` reports `aggregateIdRequired: true`, requiring a per-call aggregate ID. The executor resolves the explicit `aggregateId` argument first, then the accessor value, then the Query constant. An explicit value must agree with an accessor value but intentionally overrides a constant. An invalid explicit argument, an explicit/accessor conflict, or a missing value yields `validation_failed` at `/aggregateId`. If a non-null mapped accessor alone supplied the invalid value, use its escaped RFC 6901 Payload pointer. An unmapped interface getter or constant uses `/aggregateId`. Both Heads return the same violation before any submission.

### AD-20 — Paging is Envelope-only

- **Binds:** Core, both heads, FR-9, FR-17
- **Prevents:** paging carried both in the Payload and in the Envelope, or by different members in each head.
- **Rule:** `pageSize`, `offset`, `cursor` exist only as `RunQueryArguments` members and map to `SubmitQueryRequest.Paging`; `QueryResult.Paging` maps `Metadata.Paging`. MCP requires Int32 integer tokens for `pageSize` and `offset`. A string, fraction, lexical `25.0` or out-of-range number fails with JSON-RPC `InvalidParams` before invocation. The CLI reports a malformed or out-of-Int32 numeric option as `invalid_arguments`. After binding, Core rejects a supplied `pageSize` outside 1–200, an `offset` outside 0–2,147,483,647, a `cursor` longer than 4,096 UTF-16 code units, or a nonblank `cursor` combined with any supplied `offset`, including zero, returning `validation_failed` at `/pageSize`, `/offset`, or `/cursor` before any Gateway call. Both Heads preserve module-specific paging and filtering semantics. Handlers or deployments may enforce narrower limits. AD-20’s response rule below governs the returned metadata. A Query Payload member named `PageSize`, `Offset`, or `Cursor` is ordinary Payload and a `describe --lint` warning `payload_paging_member`; it never supplies generic paging. Exposed paged handlers must consume `QueryEnvelope.Paging`; upstream migration and live semantic evidence are mandatory for Tenants readiness (AD-16), even if legacy Payload members remain for other clients.

- **Response contract.** Core omits `paging` when Gateway metadata or its paging member is absent or null. Apply §G to the decoded paging values under the pinned Gateway client’s conversion rules while the actual HTTP status is available. The resulting public object requires an integer `pageSize` greater than zero. Independently optional `offset` and `totalCount` are nonnegative integers, `nextCursor` is a nonempty string and `hasMore` is a boolean. Omit unavailable optional members. Preserve a returned zero count or offset and `hasMore: false`. The request ceiling of 200 applies only to input. Preserve supported numeric strings on the wire, including a signed or zero-padded integer that decodes to a valid value. A decoding failure or invalid decoded paging object produces a single §G `gateway_error` carrying that status (including 2xx) and bounded detail. Both Heads return the same error object after one Query submission. CLI exits 2 and MCP sets `isError: true`.
- **Implementation gap.** The packaged loopback fixture expects empty paging to produce `pageSize: 0`. The CLI and stdio tool emit that result. The MCP session’s advertised success schema rejects it. McpCli and EventStore must preserve status through the response adapter and correct the fixture. Acceptance covers absent/null paging, supported quoted integers including signed and zero-padded forms, null optional members, zero offsets and counts, false continuation flags, and malformed paging including a missing, zero or negative page size. For each case compare the actual CLI JSON and MCP structured content against each other and the schema advertised by the same MCP session. ## Deferred

- **Hosted HTTP.** The shipped host uses stdio. Selecting HTTP fails before serving. AD-10 specifies the K10 authority boundary and Platform admission criteria.
- **Generic query extensions.** Dedicated search, filter, ordering, freshness and conditional HTTP features (`ifNoneMatch`, `ETag`, `IsNotModified`) are deferred. A Module replacement still has to prove the supported Payload and handler behavior under K03, including filtering before Envelope paging and correct continuation. AD-20 governs generic paging. Query correlation and extensions require a compatible Gateway client.
- **Command status and retries.** The caller can trace a Command by its message identifier. The generic tool exposes no status lookup or automatic retry. AD-9 governs caller retries after an unknown outcome.
- **Other surfaces.** Generated per-Operation subcommands or typed tools, shell completion, event streams, plug-in loading, and MCP resources and prompts remain parked. Broader analyzer rules, AOT or trimming, and additional Decoration Package targets require their own compatibility evidence. CLI table layout and help text belong to the CLI adapter.
