# Architecture validation — adversarial seam review — 2026-09-23

**Verdict: change needed before independently built Catalog, Schema, and executor units use the decoration contract.** One high and one medium finding. This is a document-level validation; the production McpCli projects do not yet exist. The spine and its inputs were not edited.

## Scope

Reviewed the current `../ARCHITECTURE-SPINE.md`, PRD `../../../prds/prd-mcpcli-2026-09-21/prd.md`, normative `../../../prds/prd-mcpcli-2026-09-21/addendum.md`, and the pinned EventStore request contracts in `references/Hexalith.EventStore`. In particular, checked shared Payload ownership, state mutation, Envelope resolution, protocol boundaries, and the operational envelope. Existing rules already bind call-kind rejection, pre-fill versus accessor ordering, command root shape, output documents, read-only enforcement, profile transactions, stdio channel ownership, and the deferred HTTP authentication design. Those are not reopened here.

## ADV-01 — High — Envelope role aliases have no collision rule

**Locations.** Spine AD-3, line 73, stores `EnvelopeFilledProperties` as a set; AD-7, line 97, defines that set from `tenantProperty`, `correlationProperty`, `idempotencyKeyProperty`, and `actorProperty`; AD-9, line 109, compares then overwrites those members and resolves the aggregate accessor afterward. AD-19, line 169, reads `aggregateIdProperty` from the final Payload. The PRD's attribute table at lines 135–142 gives each member an independent meaning, but its `tenant_is_aggregate_id` diagnostic at lines 220–221 covers only one pair. The addendum's §E inputs can provide a different Tenant, Actor, Correlation ID, and aggregate identifier in the same call.

**Two compliant units.** A Module declares `tenantProperty = "PrincipalId"` and `actorProperty = "PrincipalId"` on a Command with one settable string property. The raw Payload omits it; session Tenant is `acme` and Actor is `user-1`. A Catalog unit can include the Command: no stated diagnostic excludes this configuration, and its set of envelope-filled properties collapses the two roles into one. An executor unit that fills Tenant then Actor sends `PrincipalId: "user-1"`; another that fills Actor then Tenant sends `PrincipalId: "acme"`. Both follow the instruction to overwrite each named member, and both can submit a schema-valid request. The Gateway Envelope remains `Tenant: "acme"` in either case, while the domain Payload differs.

The same defect covers `correlationProperty = aggregateIdProperty`: after the correlation overwrite, AD-19 can route the Command to the generated or caller-supplied correlation identifier rather than its intended aggregate. `actorProperty = aggregateIdProperty` has the same class of ambiguity. The existing `tenant_is_aggregate_id` diagnostic does not cover these pairs. Equality should be checked on the **effective serialized JSON property** as well as the declared CLR member: Module options and `[JsonPropertyName]` can change the wire name. A simple CLR-name comparison alone is not a complete rule.

**Disposition.** Amend the Catalog invariant to bind each envelope role and the aggregate accessor to one effective serialized property and exclude an Operation when distinct roles resolve to the same property (retaining the existing `tenant_is_aggregate_id` category for that specific collision, or defining one general collision category). The executor can then assume unique ownership. Add a synthetic decorated Command for two-role overlap and one for aggregate overlap; assert exclusion before either head advertises them. This is an architecture correction, with a matching PRD diagnostic entry.

## ADV-02 — Medium — Attribute property names are not mapped unambiguously to serialized JSON names

**Locations.** Spine AD-6, line 91, fixes `PropertyNamingPolicy = null` but allows a Module's converters; AD-7, line 97, transforms and validates the serialized Schema; AD-19, line 169, says only that an `aggregateIdProperty` uses “a JSON Pointer read of that member.” The PRD attribute table, lines 135–142, calls these values Payload properties without defining whether their strings are CLR member names or wire names. PRD FR-7, lines 233–240, and addendum §G, lines 290–291 and 351–356, require Schema and public property pointers to use the Module's serialized contract. [Microsoft's System.Text.Json documentation](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/customize-properties#customize-individual-property-names) confirms `[JsonPropertyName]` changes the serialized name in both directions even when a naming policy is set.

**Two compliant units.** A decorated Command declares `aggregateIdProperty = nameof(PartyId)` and a property `[JsonPropertyName("party_id")] public string PartyId { get; init; }`. A Catalog unit can treat the attribute as the CLR property and compile a pointer from serializer metadata to `/party_id`; another can treat the literal attribute string as a JSON name and compile `/PartyId`. Both are plausible readings of “read of that member.” The same valid caller Payload `{ "party_id": "party-1" }` then succeeds through one Catalog/executor pair and returns `validation_failed` at `/aggregateId` through the other. `tenantProperty` and other envelope fields have the analogous fill/compare ambiguity. The current Tenants and Parties source has no decorated release yet, so this is a supported-contract counterexample rather than a claim of a current production failure.

**Disposition.** Define attribute property strings as CLR property names and resolve them once through the cached `JsonTypeInfo`/`JsonPropertyInfo` to effective serialized names; use those names for Schema transforms, raw/rebuilt Payload pointers, lint pointers, and collision checks. Exclude an Operation when a declared name cannot be resolved to one eligible serialized member. A single `[JsonPropertyName]` fixture that exercises Schema, Catalog accessor, and executor would close the seam. This is an architecture correction; the PRD table should state the same naming rule.

## Boundaries checked without a finding

- Profile data has one writer, a cross-process transaction, and immutable per-process settings (AD-11, AD-13, AD-14). The HTTP request identity design is explicitly deferred before its release (AD-10, Deferred), so a future per-request `Actor` mechanism is not a v1 finding.
- The MCP server owns stdout as JSON-RPC, while the CLI owns result rendering and exit codes (AD-1, AD-12, Channels convention). The global `--output` flag's behavior under `mcp` could use a help-text clarification, but the stdout rule already prevents routing JSON-RPC through the CLI output writer; no incompatible compliant execution was demonstrated.
- Read-only enforcement occurs in Core even if an adapter misadvertises a tool (AD-3, AD-9, AD-12). No second state mutation path was found.
- The Aspire/CI and first decorated package prerequisites are explicit Open Questions at spine lines 326–330; they are tracked readiness gates, not missing v1 operational decisions.
