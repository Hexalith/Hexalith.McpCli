## ADV-01 · High · A Query success can violate its advertised paging schema

AD-20 maps returned paging metadata directly. The Query-results convention preserves returned zero values. AD-5 binds both Heads to §G, which requires a positive `pageSize`, nonnegative offset and total, and a nonempty continuation when present. Given a Gateway success with an empty paging object, a direct mapper emits `{"paging":{"pageSize":0}}`. A mapper enforcing §G must withhold that success. An MCP client validating structured content will reject what the CLI and conformance runner accept. [AD-5, line 109](../ARCHITECTURE-SPINE.md#L109) · [AD-20, line 228](../ARCHITECTURE-SPINE.md#L228) · [Query results, line 276](../ARCHITECTURE-SPINE.md#L276) · [§G, lines 424–438](../../../prds/prd-mcpcli-2026-09-21/addendum.md#L424)

The executor copies all five metadata fields. The packaged-process fixture expects a missing size to become zero. The MCP schema tests reject that identical size, negative counts and an empty continuation. Running the repository's Python SDK-response model confirmed the zero, negative-offset and empty-cursor projections. Specify that a malformed paging object produces a shared `gateway_error` at the HTTP response boundary with the actual status. Preserve valid zero offsets, zero totals and explicit `hasMore: false`. Run both Heads against the same malformed replies and validate each result against the advertised schema. [Executor, line 279](../../../../../src/Hexalith.McpCli.Core/Execution/OperationExecutor.cs#L279) · [Packaged-process fixture, line 59](../../../../../tools/conformance-vectors/v1/run_packaged_process_fixture.py#L59) · [SDK-response model, line 507](../../../../../tools/conformance-vectors/v1/run_loopback.py#L507) · [Schema tests, line 305](../../../../../tests/Hexalith.McpCli.Mcp.Tests/McpOutputSchemaTests.cs#L305)

An absent or null paging object already omits `paging` from the result. The disagreement begins when a present object omits its required size, which the typed response defaults to zero, or contains an explicitly invalid value.

## ADV-02 · Medium · A Query constant can make an optional argument mandatory

AD-19 permits a Gateway-valid aggregate constant. AD-8 and FR-15 require the resolved aggregate identifier to obey the Module's Identifier Kind. The `Ulid` fixture declares `routing-list`, which meets the Gateway grammar. Its Catalog test requires `aggregateIdRequired: false`. Calling it with no override selects that constant and fails ULID validation at `/aggregateId`. A Catalog that checks the Module kind at admission would exclude the same Query. This discrepancy affects discovery and the normal call for supported ULID Modules. Require constants to satisfy both grammars at Catalog build and classify a failure as `invalid_routing_value`. Use a canonical ULID for the positive fixture and verify omission works through both Heads. Keep explicit overrides of valid constants. ## ADV-03 · Medium · AD-7 removes valid serializer inputs

AD-7 and FR-7 direct the exporter to remove getter-only members lacking a constructor parameter and to set `additionalProperties: false`. Implementing both literally rejects an input such as `{"Tags":["a"]}` when System.Text.Json populates the getter-only collection in place. It also rejects entries in a typed dictionary, where the serializer exports a value schema under `additionalProperties`. The shipped Core and existing schema tests support both shapes. A caller would receive a different `describe` schema and a different validation outcome for the same declaration. [AD-7, line 121](../ARCHITECTURE-SPINE.md#L121) · [FR-7, line 260](../../../prds/prd-mcpcli-2026-09-21/prd.md#L260) · [Resolver, line 131](../../../../../src/Hexalith.McpCli.Core/Serialization/McpCliJson.cs#L131) · [Typed dictionary test, line 372](../../../../../tests/Hexalith.McpCli.Core.Tests/SchemaTests.cs#L372) · [Populate tests, line 508](../../../../../tests/Hexalith.McpCli.Core.Tests/SchemaTests.cs#L508)

Specify that the effective serializer contract determines input membership, including property-level and type-level `Populate`. Close object records against unknown fields and retain the exported value schema for supported typed dictionaries. The existing free-form and opaque-member exclusions continue to govern supported value types. [Schema transform, line 346](../../../../../src/Hexalith.McpCli.Core/Schema/SchemaDeriver.cs#L346)

## ADV-04 · Medium · Aggregate validation names two different correction targets

AD-9 and FR-15 assign aggregate grammar violations to `/aggregateId`. The §G example points to `/PartyId`. With a String Module's mapped `Key` equal to `bad/id`, the executor and its regression return `/Key`. Supplying the same invalid string as an explicit argument changes the path to `/aggregateId`. A client using the validation pointer to choose what to correct edits different input under the two interpretations. ## ADV-05 · Medium · A Catalog containing only marked empty Modules has two possible discovery outcomes

AD-4 and FR-20 promise visibility for a marked empty Module. AD-3 rejects an empty Catalog on discovery without specifying whether emptiness counts Modules or valid Operations. With one marked Module and zero Operations, one implementation returns its row and warning. Core instead returns `catalog_empty` and no result. Under `--strict`, the same warning changes the error to `catalog_invalid`. The CLI suite pins all four combinations of empty manifest versus marked empty Module and strict versus ordinary discovery. [AD-3, line 95](../ARCHITECTURE-SPINE.md#L95) · [AD-4, line 103](../ARCHITECTURE-SPINE.md#L103) · [FR-6, line 252](../../../prds/prd-mcpcli-2026-09-21/prd.md#L252) · [FR-20, line 438](../../../prds/prd-mcpcli-2026-09-21/prd.md#L438) · [Catalog gate, line 31](../../../../../src/Hexalith.McpCli.Core/Catalog/CatalogProvider.cs#L31) · [CLI matrix, line 506](../../../../../tests/Hexalith.McpCli.Cli.Tests/DiscoveryCommandTests.cs#L506)

Define public Catalog emptiness as zero valid Operations across all Modules. Apply strict diagnostics first. State that an empty Module appears in ordinary discovery when another Module contributes a valid Operation.
