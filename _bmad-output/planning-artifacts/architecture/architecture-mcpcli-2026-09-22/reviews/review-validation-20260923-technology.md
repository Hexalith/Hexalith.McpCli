# Technology and source-reality validation — 2026-09-23

**Verdict: conditional.** The pinned stack and MCP/Gateway API choices are real and substantially compatible with the checked sources. Two **High** Tenants integration gaps remain before the claimed v1 live gate and coverage can be treated as ready. They are upstream compatibility prerequisites, not reasons to abandon the hexagonal shape.

## Findings

### High — the Tenants audit query silently loses its filters under the chosen Payload wire casing

**Spine location:** `ARCHITECTURE-SPINE.md:91` (AD-6), `:97` (AD-7), `:145` (AD-15), `:151` (AD-16).

**Evidence:** AD-6 fixes the Module Payload options to case-sensitive CLR names (`PropertyNamingPolicy = null`), including for Queries; AD-7 derives the query schema from those options. The current `GetTenantAuditQuery` contract has `From`, `To`, and `Category` members (`references/Hexalith.Tenants/src/Hexalith.Tenants.Contracts/Queries/GetTenantAuditQuery.cs:15-19`). Its live handler reads raw JSON with `TryGetProperty("from")`, `"to"`, and `"category"` (`references/Hexalith.Tenants/src/Hexalith.Tenants/Queries/Handlers/TenantQueryHandlerBase.cs:301-319`). `JsonElement.TryGetProperty` performs an [ordinal, case-sensitive match](https://learn.microsoft.com/en-us/dotnet/api/system.text.json.jsonelement.trygetproperty?view=net-10.0). Thus a schema-valid `{ "From": ..., "To": ..., "Category": ... }` payload passes the tool but is treated by today's handler as having no filters. A camelCase payload is rejected by the tool's schema and `UnmappedMemberHandling = Disallow`. The command side explains why the chosen PascalCase baseline exists: Tenants command validation currently deserializes with default `JsonSerializer.Deserialize<TCommand>` options (`references/Hexalith.Tenants/src/Hexalith.Tenants/Validation/TenantSubmitCommandValidator.cs:64-72`), for which [property matching is case-sensitive by default](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/character-casing).

**Disposition:** Discuss and make a named Tenants Gateway-ready prerequisite before v1 coverage is claimed. Either change the upstream audit handler to consume the declared CLR-name wire shape or establish an explicit, operation-specific wire convention with matching schema, executor, and upstream tests. A single Module-wide provider cannot fix this because AD-6 discards its non-converter settings. Add a live vector with non-default `From`, `To`, and `Category` and assert the filtered semantic result, not merely a successful response. Keep the current source behavior visible as an open prerequisite until that test passes against the decorated Tenants release.

### High — Envelope-only paging is currently ignored by Tenants query handlers

**Spine location:** `ARCHITECTURE-SPINE.md:175` (AD-20), `:151` (AD-16), `:318` (Deferred).

**Evidence:** AD-20 sends `pageSize`, `offset`, and `cursor` only in `SubmitQueryRequest.Paging`, while the pinned Gateway forwards that into the query envelope (`references/Hexalith.EventStore/src/Hexalith.EventStore/Controllers/QueriesController.cs:84-99`; `references/Hexalith.EventStore/src/Hexalith.EventStore.Contracts/Queries/QueryEnvelope.cs:265`). The current Tenants `ListTenants`, `GetTenantUsers`, `GetUserTenants`, and `GetGlobalAdministrators` handlers call `DeserializePaginationPayload(envelope.Payload)`, which reads lower-case `cursor` and `pageSize` from JSON (`references/Hexalith.Tenants/src/Hexalith.Tenants/Queries/TenantQueryPaginationPayloadParser.cs:14-39`). `GetTenantAudit` also takes its cursor and size from Payload (`TenantQueryHandlerBase.cs:303-333`; `GetTenantAuditQueryHandler.cs:49,76`). No handler found in the current Tenants query source reads `envelope.Paging`. Therefore a tool call specifying only envelope paging will still use the handler's default first page. AD-20's Deferred note recognizes a pending Tenants decision, but AD-16 nevertheless describes a blocking live tier with Tenants included.

**Disposition:** Promote the Tenants paging migration to an explicit v1 Gateway-ready prerequisite, with an upstream change that consumes `QueryEnvelope.Paging` or an approved revision of AD-20/PRD if payload-level paging must remain. The live vector must request a non-default size and a subsequent cursor and assert those semantics. A successful Gateway status or merely populated paging metadata would not prove that the Tenants handler honored the request.
