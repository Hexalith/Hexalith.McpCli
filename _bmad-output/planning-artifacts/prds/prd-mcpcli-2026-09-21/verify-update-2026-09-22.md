## Contradictions and dangling references

1. **CLI `--tenant` is both the FR-13 session flag and the §E per-call argument, so the FR-16 gate is undecidable on the CLI.** FR-13 (prd:248): "Every verb accepts `--url`, `--token`, `--tenant`, … every other option then resolves as flag, environment variable, selected Profile, default. Only `tenant` also has a per-call source, governed by FR-16." Addendum §E row (add:177): "tenant | `send_command`, `run_query` (optional) | `--tenant` (global) | the only per-call identity value; honored per PRD FR-16 (fixed tenant, then operator gate)". FR-16 c2 (prd:285): "the per-call argument, honored only when no Tenant resolves from flag, environment, or Profile, or when `allowTenantOverride` is set". On `hexalith send parties.create-party --tenant beta` with a Profile tenant `acme`, one engineer treats `--tenant beta` as the flag (beats the Profile in the FR-13 chain, no gate) and another as the per-call argument (`validation_failed` unless `allowTenantOverride`). The §E resolution-order paragraph (add:195–198) says "Only `tenant` has a per-call source in addition" without saying what the CLI spelling of that source is. The CLI needs either a distinct per-call spelling or a sentence saying the CLI has no per-call tenant source and `--tenant` is always the session flag.

2. **The per-call tenant rule is stated three ways and they disagree.** §4 Tenant (prd:82): "a per-call value is honored only where the operator has allowed it." §3 Tenant (prd:68): "a per-call argument the operator has allowed." FR-16 c2 (prd:285): honored "when no Tenant resolves from flag, environment, or Profile, or when `allowTenantOverride` is set". Under FR-16 an unconfigured session honors the LLM's tenant with no operator action, which §4 and §3 forbid on their face. §0 promises each guardrail is stated once in §4 and referenced elsewhere; here §4 and FR-16 are both normative and differ. Either §4 should say "honored only when no session Tenant is configured or where the operator has allowed it", or FR-16 should drop the no-default branch.

3. **Sample Module count: one or two.** §4 (prd:80): "plus one synthetic sample Contracts Library never referenced by the tool package." §8.1 item 1 (prd:377): "Test fixture Contracts Library (§4)" (singular). NFR-1 (prd:355): "The Catalog for the v1 Modules plus the two sample Modules builds in under 500 ms". A Module marker is per assembly, so two sample Modules need two libraries.

4. **§G `describe_operation` lists `tenant` as a suppliable argument on a fixed-tenant Operation.** Addendum §G (add:271): `"envelope": { "fixedTenant": "system", "aggregateIdRequired": false, "arguments": ["tenant", "aggregateId", "entityId", …] }` for `tenants.get-tenant-users`. FR-9 c2 (prd:209) defines `arguments` as "the Envelope arguments the caller may supply"; FR-16 c2 (prd:285) makes any differing per-call value `validation_failed`; UJ-1 (prd:38) says the description tells the agent "the Envelope tenant is fixed to `system`, so the agent passes none". Listing `tenant` invites the agent to supply it. Either omit `tenant` from `arguments` when `fixedTenant` is set, or define `arguments` as "accepted" rather than "may supply".

5. **§G carries members and codes no FR names.** `list_modules` example (add:254) has `"operationCount": 6`; FR-9 c2 (prd:209) says `list_modules` "returns each Module Name with its description". §G code list (add:303–305) includes `internal_error`, which appears in no FR (FR-11 names `validation_failed`, `gateway_error`, `unknown_operation`; FR-14/FR-19/FR-12/FR-6/FR-18 name the rest). Since §G is normative these are additions rather than errors, but FR-9 and FR-11 should mention them or §G should not.

6. **Query results and the correlation identifier (H1 residue).** FR-16 lead (prd:281): "for Commands passes a caller-supplied correlation identifier … through"; FR-17 c1 (prd:298): "Command results include … the Gateway's correlation identifier"; FR-17 c2 (prd:299) for Queries: "the document and, when paging applies, …". Nothing says whether a Query result or a Query-side `gateway_error` carries a correlation identifier, while the §G `gateway_error` document (add:296) always shows `"correlationId"`. State it either way.

7. **UJ-1's retry uses a key the timed-out call never returned.** UJ-1 (prd:38): "the second call times out; the agent retries with the idempotency key from its first attempt." §E (add:180): idempotency key is "generated when absent; returned in the result". So on a timeout the agent has no key unless it supplied one. Either the journey should say the agent supplies the key up front, or the error document should carry the generated `messageId` and `idempotencyKey`.

12. **FR-2 c3 names a value that does not exist in the convention case.** FR-2 lead (prd:136): "the contract interface when the interface defines that field, else the attribute member, else the marker's `wireTypeConvention`". ## Ambiguities

1. **`--strict` on warnings.** FR-6 (prd:172): "any diagnostic ends the verbs that build the Catalog with exit 2 and `code: catalog_invalid`". FR-6 distinguishes error categories (type excluded) from warning categories (kept). Does a redundant-value warning or `empty_module` fail a `--strict` run? "Any diagnostic" says yes; the error/warning split suggests no.

2. **`--tenant` on the CLI** (see contradiction 1): session flag or per-call argument. Two engineers will implement opposite gate behaviour.

3. **Per-call tenant with no session Tenant** (see contradiction 2): allowed without operator action per FR-16, forbidden per §4.

4. **`wireTypeConvention` derivation rules are undefined.** §5.1 (prd:121) names `FullTypeName` and `KebabCase` without saying what they produce. `FullTypeName`: namespace-qualified or assembly-qualified? `KebabCase`: is the trailing `Command`/`Query` stripped as FR-8 does for the Operation Name (Tenants' `CreateTenantCommand` dispatches on `create-tenant`, so the answer matters), and is it the type name or the Operation Name part after any `name` override?

5. **`serializerOptionsProvider` "merged under the tool's canonical options" (prd:122).** When both define a converter for the same type, which wins? "Under" suggests the tool's options win, which would defeat a Module converter that the tool's options also cover. Also: is the provider used only for Schema derivation and Payload validation, or also when serialising the Payload that goes into the Envelope?

6. **Where the FR-15 domain check fires.** FR-15 c3 (prd:277): "Tenant and domain match the Gateway's … pattern … Each failure is a `validation_failed` entry at the field's path." Domain is a Routing Value from the Contracts Library, not a caller field: is a bad domain a Catalog diagnostic at startup (excluding the Operation) or a per-call `validation_failed`, and at which JSON path?

7. **FR-13 "every other option then resolves as flag, environment variable, selected Profile, default" (prd:248) overstates.** `--output` has no environment variable and no Profile field; `--read-only` and `--strict` have environment variables but no Profile field; `allowedExtensions` has a Profile field but no flag or variable (§E add:186–200, 209–217). An implementer must guess which sources each option really has; a per-option source table would settle it.

8. **A Profile or flag Tenant that differs from `fixedTenant`.** FR-16 c2 (prd:285) makes only a differing per-call value an error; UJ-1 (prd:38) relies on a Profile tenant `acme` being silently ignored for Tenants Operations. Nothing states that silence. Say "a session Tenant that differs from `fixedTenant` is ignored" or make it a warning.

9. **Payload paging members kept as ordinary Payload.** §8.1 Tenants (prd:397) allows "accept the lint warning"; FR-16 c7 (prd:290) says paging travels "never through Payload members". If Tenants keeps `PageSize` in its Payload, may a caller set it, and does the executor send it, strip it, or reject it? Today two paging channels remain visible to the agent, which is what M1 tried to remove.

10. **Retry-after-timeout in UJ-1** (see contradiction 7): whether the agent supplies the idempotency key up front or reads it from an error document.

11. **`arguments` in `describe_operation`** (see contradiction 4): "may supply" versus "accepted", and whether `tenant` appears when `fixedTenant` is set.

12. **FR-5 c2 "published untrimmed or with Contracts assemblies rooted" (prd:167).** Two publishing modes are offered; which one the tool package uses decides whether a trimming-related test exists.

13. **Scan order inside one assembly.** FR-6 c2 (prd:176) orders assemblies "sorted by assembly name"; FR-8 c2 (prd:197) excludes "the second in scan order" for duplicate Operation Names. Type order within an assembly is unspecified, so which duplicate survives is not deterministic across builds unless a type-level sort is named (FR-5 c3 promises byte-identical discovery output).

14. **§4 Identity: "the extension keys a call may carry … never chosen by the agent per call" (prd:83).** Read literally this forbids the agent from passing `extensions` at all; §E (add:183) makes `extensions` an agent argument whose keys must be allowlisted. Reword to "the set of allowed extension keys is an operator setting".

15. **Default Gateway URL.** FR-13 c2 (prd:252): "the default URL is the Gateway, not the admin API"; §E (add:198–199): "the URL default is the Gateway address that the architecture document designates". No value appears in either file; an implementer cannot write the default without another document.

16. **FR-16 c5 asymmetry.** A Payload value under `tenantProperty` or `actorProperty` that differs from the resolved value is `validation_failed`, while `correlationProperty` and `idempotencyKeyProperty` values are silently overwritten (prd:288). This is stated, so implementable, but a reader may take the silent overwrite for an omission; one clause saying it is intentional would prevent a "fix".

17. **Query-side `correlationId` in errors** (see contradiction 6): whether a Query `gateway_error` document carries `correlationId` when the client sets no header.
