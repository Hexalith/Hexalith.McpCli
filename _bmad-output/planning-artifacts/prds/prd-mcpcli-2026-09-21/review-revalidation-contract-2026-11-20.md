# Public contract revalidation

Reviewed the working-tree PRD and addendum on 20 November 2026 against the local Release executable, source, pinned SDK and regression tests. Seven documentation findings remain. None reopens a historical correction. The modern packet finding concerns JSON-RPC metadata around the verified tool arguments.

### High · Adding an existing profile clears omitted settings

FR-18 and §E describe profile creation and private rotation without specifying the existing-name behavior. The shipped `config profile add dev --url …` replaces the entire `dev` record. It clears an existing token, format, tenant, actor, override setting and extension allowlist when omitted. Treating it as a field update loses configuration. Specify that an explicit URL is required, only explicitly supplied connection fields are stored, and existing-name replacement preserves other profiles and the active selection. Explicit operator flags on `add` are refused before writing. Distinguish the current command from Story 5.16’s planned private rotation. ### Medium · Profile management bypasses session profile selection

FR-13 and §E apply the selected-profile chain to every verb. FR-18 also says absence of the flag selects the active profile, overlooking `EVENTSTORE_PROFILE`. In a read-only probe with the same nonexistent selector, `config current --profile review-absent` returned exit 2 and `configuration_invalid`, while `config profile list --profile review-absent` returned exit 0. The management verbs `config profile list|add|remove`, `config use` and `config set` ignore both selectors and the active profile for presentation. This allows recovery from a missing selection. State which verbs resolve session settings normally, and give the management output format order of flag, environment, then JSON. Other applicable flag/environment validation still runs. ### Medium · The raw tool call does not identify the modern protocol revision

The §E example's operation, JSON payload string and other tool arguments match the approved Tenants vector. Its complete JSON-RPC packet is usable after legacy initialization. For MCP 2026-07-28, SDK 2.4.0 requires the protocol version and client capabilities on each request. On the local stdio host following modern `server/discover`, the literal packet yielded the legacy result envelope without `resultType`. Adding `params._meta` with `"io.modelcontextprotocol/protocolVersion":"2026-07-28"` and `"io.modelcontextprotocol/clientCapabilities":{}` produced the modern result with `resultType` and server metadata. Both reached the same offline tool error. Label the current example as legacy and show these two metadata fields for the modern packet. The SDK's pinned `ModelContextProtocol.Core.xml`, lines 13357–13370 (`McpServerImpl.PrependMetaReadingFilter`), specifies the requirement. ### Medium · The paging input row omits two distinct error boundaries

In both supported MCP revisions, the Release host rejected raw `pageSize: 25.0` with JSON-RPC `-32602`. A bound `pageSize: 201` instead produced a tool result with `validation_failed` at `/pageSize`. §E names these inputs without their wire types, limits or stage of failure. Specify that `pageSize` and `offset` require integer tokens representable as Int32. Core allows page sizes 1–200 inclusive, nonnegative offsets and cursor strings up to 4,096 UTF-16 code units. A nonblank cursor conflicts with a supplied offset. Qualify these as generic limits because modules can apply narrower paging rules. ### Low · The query aggregate constant is optional

The §5.1 declaration table requires a constant for a list-style Query with no aggregate property. FR-2 and §E correctly allow the caller to supply the aggregate on each call. The Catalog has no list-specific exclusion and advertises `aggregateIdRequired: true` when both declaration sources are absent. Mark the constant optional and retain its mutual exclusion with the property. ### Low · The served-request rule also appears to cover host faults

FR-6 and FR-10 say all failures after serving begins travel only through JSON-RPC. §G and the process test identify a distinct process outcome. A faulted hosted service exits 2 and writes the fixed stderr diagnostic `MCP server stopped unexpectedly.` Scope the PRD statements to request failures and refer host termination to §G. Otherwise a conforming host fails the stated acceptance criterion. ### Checks on the historical corrections

A different canonical acknowledgment message ID was returned with the submitted correlation. Malformed JSON and a missing acknowledgment correlation produced `gateway_error` with the actual 200 and 202 statuses respectively. The shipped executor still accepted a present noncanonical ID, as the documented Story 5.17 backlog anticipates. No live deployment was used.
