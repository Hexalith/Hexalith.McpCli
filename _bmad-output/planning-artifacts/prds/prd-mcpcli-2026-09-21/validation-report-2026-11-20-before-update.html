A CLI command can exit 2 after the Gateway accepts it

PRD FR-14, lines 338–346 and addendum §E, output setting

Correction. Document both outcomes, the success destination selected by --output, and interruption exits separately. Direct callers with an uncertain outcome to check state before considering another submission. ExecutionFailureCommandTests.cs, line 137

Correction. State the correlation and message ID rules separately. Cover a deliberately different acknowledgment correlation ID in the example or acceptance criterion. OperationExecutorTests.cs, line 154

Downstream usability

Thin

Stable requirement IDs and field tables aid implementation. The HTTP handoff, query declaration table and portions of the public protocol contract would send implementers in the wrong direction.

High

The planned HTTP transport would forward the wrong credential

PRD §8.2, line 526 and addendum §B, lines 90–92

The addendum directs implementers to reuse the Parties handler, which copies the incoming bearer token. Adopted decision K10 requires token exchange and attestation of the actor and effective origin for a shared HTTP service. The issue concerns the proposed HTTP design. The shipped service uses stdio.

Correction. Revise OQ-1 and the transport handoff to require token exchange, issuer and audience checks, attestation, and denial evidence. Identify the Parties handler as historical context. AD-23-non-gateway-capability-classes.md, line 233

High

The projection rule would exclude an enrolled Projects query

PRD §5.1, lines 147–148 and FR-20, line 430

The declaration table requires projectionType for a query without IQueryContract. The approved projects.list request has neither projection selector. Enforcing the table could exclude the query or change its Gateway route.

Correction. Allow computed queries to omit both selectors. Require a resolved projectionType when projectionActorType is supplied, matching the routing resolver and the approved vector. list.vector.json, line 22

Medium

The MCP payload row omits its outer wire type

Addendum §E, lines 203–212

The operation schema describes the decoded payload. Both execution tools advertise their outer payload argument as a string containing JSON text. A caller sending an object directly fails at protocol binding.

Correction. Declare the required string type and show a complete tool call with serialized JSON. Keep CLI file and stdin syntax in the CLI column. McpToolHandlers.cs, line 49

Medium

A bound MCP value can still fail as a structured tool error

Addendum §G, lines 465–486

The addendum assigns invalid_arguments to CLI binding. An MCP argument that passes type binding can still produce a structured invalid_arguments result, for example the unsupported case-sensitive kind value Read. CLI parser argument names can also fall outside the §E table.

Correction. Distinguish JSON-RPC binding errors from structured errors after binding. Align the permitted argument names with the public result schema. McpProtocolTests.cs, line 134

Medium

The serializer provider declaration omits its type and failure mode

PRD §5.1, line 166 and FR-6, lines 227–247

The attribute expects a provider Type from the Contracts assembly with a public static JsonSerializerOptions Options getter. Passing a static member as the table suggests does not express that contract. Invalid providers exclude the whole module and produce a specific diagnostic.

Correction. Specify the attribute type and getter signature, and add invalid_serializer_options_provider with its module-wide effect to FR-6. McpCliJson.cs, line 38

Low

Two normative JSON examples use abbreviated ULIDs

Addendum §G, lines 374, 430 and 514

The command success and Gateway error examples use 01J9… in four identifier fields. They parse as JSON, but the identifiers fail the canonical ULID grammar. The advertised send_command output schema rejected the sample in the local check.

Correction. Use complete synthetic uppercase ULIDs in both examples so they can be reused as schema fixtures. SchemaDeriver.cs, line 18
