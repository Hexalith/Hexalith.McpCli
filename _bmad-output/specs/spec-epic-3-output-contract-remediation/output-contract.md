# Output contract requirements

PRD FR-11 and addendum §G define the public contract; architecture AD-1/3/5/6/8/12 define ownership. This remediation strengthens the advertised contract without inventing new document fields or restricting embedded content. The implementation and its fixtures must cover every applicable row below.

## Ownership and schema boundaries

Core owns the typed records and the semantic metadata/rules used to derive their schemas. Reuse Core naming, Gateway syntax, canonical ULID, and availability rules. The MCP adapter may translate that metadata into JSON Schema and assemble the advertised success/error union; semantic constants and conditions must not become a separate MCP policy table. Core continues to reference no MCP, System.CommandLine, or ASP.NET package. Preserve the existing dependency direction and Contracts enrollment policy.

Each advertised schema has an object root and exactly the existing `oneOf` alternatives: a closed success document and a closed `{ "error": ... }` document. Close canonical nested document objects, including summaries, envelope, paging, lint findings, error variants, and violations. Preserve §G required fields, types, enum/constant values, and empty-array behavior. Optional canonical members are omitted when absent and reject explicit null. Explicit null remains valid inside arbitrary JSON values.

Schemas enforce rules determined by the document itself. Core-produced fixtures separately prove external facts: declared Catalog membership, counts, suggestion ordering, example validity against the returned Module schema, descriptor-requiredness, and resolved session availability. Do not enumerate Modules/Operations into a changing tool surface or copy execution policy into MCP to enforce those facts.

## F1 reproduction obligations

Preserve independently specified fixtures for each retrospective counterexample: query page size 0; offset −1; total count −1; empty next cursor; command non-ULID message ID; negative Module operation count; empty Module name and description (test each independently); empty validation violations; four `unknown_module` suggestions; unavailable description missing its reason; invalid lint code and severity (test each independently); and a property-level lint finding missing its pointer. Each must fail against the final actual advertisement under both revisions. The matrix extends this minimum to equivalent fields/branches so one repaired example cannot conceal another missing constraint.
